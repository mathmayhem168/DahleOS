# Git / GitHub Quick Reference Card

---

## Commit Message Format

```
<type>(<scope>): <short summary>

<optional body — explain WHY, not WHAT>
```

- **Imperative mood** — "add matrix command" not "added" or "adding"
- **No period** at the end of the summary
- **72 characters max** on the summary line
- **Lowercase** after the colon

---

## Commit Types

| Type       | Use when                                              | Example |
|------------|-------------------------------------------------------|---------|
| `feat`     | New feature, command, or capability                   | `feat(shell): add matrix command` |
| `fix`      | Bug fix                                               | `fix(ata): handle timeout on missing disk` |
| `refactor` | Code restructure — no behavior change                 | `refactor(gui): extract widget drawing` |
| `docs`     | Documentation only                                    | `docs: update build instructions` |
| `chore`    | Build system, tooling, config, gitignore              | `chore: add disk.img to gitignore` |
| `perf`     | Performance improvement                               | `perf(screen): reduce redundant redraws` |
| `revert`   | Reverting a previous commit                           | `revert: undo broken ATA changes` |

---

## Scopes (DahleOS specific)

Use the directory or subsystem name as the scope:

`shell` · `ata` · `fs` · `gui` · `keyboard` · `persist` · `cpu` · `libc` · `boot`

---

## Commit Body: When and How

**Use it when** the reason for the change isn't obvious from the summary.

```
fix(persist): save aliases on every alias command

Previously aliases were only saved on explicit `save` calls.
A crash would lose all session aliases. Auto-saving on every
write ensures no data is lost without user intervention.
```

**Skip it when** the summary is self-explanatory (`docs: fix typo in README`).

## Versioning: Tags vs. Messages

| ❌ Old way (wrong)            | ✅ New way (correct)            |
|-------------------------------|----------------------------------|
| `feat: add matrix cmd v2.3.0` | `feat(shell): add matrix command` |
| Version buried in message     | Version lives on a git tag       |

### Tagging a release
```bash
git tag -a v0.2.4 -m "Brief description of this release"
git push origin v0.2.4
```

### Semantic Versioning: MAJOR.MINOR.PATCH

| Bump   | When                                        |
|--------|---------------------------------------------|
| MAJOR  | Breaking change — something working now breaks |
| MINOR  | New feature, backwards compatible           |
| PATCH  | Bug fix, no new features                    |

> You are in active development → stay on `v0.x.y` until stable enough for `v1.0.0`

## Daily Workflow

```bash
# Start of session
git status                        # know your state
git checkout -b feat/my-feature   # start a branch (for bigger changes)

# While coding — commit when one logical unit is done
git add -p                        # stage selectively, review each hunk
./tools/commit.sh                 # interactive commit + build check + optional tag

# End of session
git push
git push origin vX.Y.Z            # tags must be pushed separately
```

---

## Branching

```bash
git checkout -b feat/my-feature   # create and switch
git push -u origin feat/my-feature # push branch to GitHub
git checkout main && git pull      # sync main after merging
git branch -d feat/my-feature      # delete local branch after merge
```

### Branch naming
```
feat/matrix-command
fix/ata-timeout-bug
refactor/gui-widget-extraction
docs/build-instructions
chore/clean-unused-headers
```

### What goes on `main`
Only finished, working code. Never commit broken code to `main`.

---

## Atomic Commits

One commit = one logical unit of work, describable in one sentence **without "and"**.

> ❌ "Add matrix command **and** fix cursor bug" → two commits  
> ✅ `feat(shell): add matrix command` + `fix(screen): clean up cursor on exit`

## What to Ignore (`.gitignore`)

```gitignore
*.o           # compiled objects
os.bin        # kernel binary — reproducible from source
dahleos.iso   # ISO — reproducible from source
disk.img      # disk image — 1MB binary, regenerated by make run
iso/          # ISO staging dir
.DS_Store     # macOS junk
```

**Never commit:** binaries, build artifacts, disk images, secrets, editor config.

## Useful Commands

```bash
git diff                  # unstaged changes
git diff --staged         # staged changes (what will be committed)
git log --oneline -10     # recent history at a glance
git log --oneline --decorate -10  # history with tags and branches
git add -p                # stage interactively, hunk by hunk
git stash                 # shelve uncommitted work temporarily
git stash pop             # restore stashed work
git tag                   # list all tags
git show v0.2.3           # inspect a tag
git diff main...HEAD      # all changes since branching from main
git log main..HEAD        # all commits since branching from main
```

## Red Flags

| You see this                        | It means                                |
|-------------------------------------|-----------------------------------------|
| Commits: `fix`, `update`, `stuff`   | Not thinking about the message          |
| Version numbers in commit messages  | Tags aren't being used                  |
| `disk.img` or `*.bin` committed     | Missing `.gitignore` rules              |
| Everything committed to `main`      | No branching habit                      |
| 2000-line PRs                       | Feature wasn't broken into steps        |
| `wip` / `temp` branches open for weeks | Branches used as parking lots        |
